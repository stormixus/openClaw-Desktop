# Internationalization (i18n)

## Overview

openClaw Desktop supports **English** and **Korean** with a custom i18n system built on Svelte stores.

## Architecture

```
src/lib/i18n.ts              # Core i18n setup
src/lib/lang/en/index.ts     # English dictionary (500+ keys)
src/lib/lang/ko/index.ts     # Korean dictionary (500+ keys)
```

## Core API

```typescript
import { t, locale, setLocale } from '$lib/i18n';

// In Svelte template
{$t('app.title')}              // "openClaw Desktop"
{$t('nav.chat')}               // "Chat" (en) or "채팅" (ko)

// Switch language
setLocale('ko');

// Read current locale
const current = $locale;       // "en" | "ko"
```

## How It Works

### Locale Resolution
```
1. Check localStorage ("openclaw.locale")
2. Detect browser language (navigator.language)
3. Map to supported locale (en/ko)
4. Fallback: "en"
```

### Translation Function
The `t` store is a `derived` store that returns a function:

```typescript
// Simplified
const t = derived(locale, ($locale) => {
  const dict = dictionaries[$locale];
  return (key: string, params?: Record<string, string>) => {
    let value = dict[key] ?? dictionaries['en'][key] ?? key;
    if (params) {
      for (const [k, v] of Object.entries(params)) {
        value = value.replace(`{${k}}`, v);
      }
    }
    return value;
  };
});
```

### Parameterized Strings
```typescript
// Definition
"forge.pptx.slides_count": "{count} slides"

// Usage
$t('forge.pptx.slides_count', { count: '12' })
// → "12 slides"
```

## Key Naming Convention

Keys follow a **dot-separated namespace** pattern:

```
<module>.<section>.<item>

Examples:
  app.title                    # App-level
  nav.chat                     # Navigation
  chat.placeholder             # Chat module
  forge.toolbar.save           # Forge toolbar
  forge.pdf.ocr.settings_title # Deep nesting OK
  settings.theme.dark          # Settings
  games.module.chess.title     # Game modules
  gateway.status.connected     # Gateway
  npc.sidebar.title            # NPC system
```

### Namespace Prefixes

| Prefix | Scope |
|--------|-------|
| `app.*` | Application-level strings |
| `nav.*` | Navigation labels |
| `chat.*` | Chat module |
| `forge.*` | Document editor (Forge) |
| `games.*` | Game hub and lobby |
| `gateway.*` | Gateway management |
| `settings.*` | Settings page |
| `onboarding.*` | Setup wizard |
| `npc.*` | NPC/Persona editor |
| `common.*` | Shared strings (cancel, save, etc.) |
| `status.*` | Connection status |
| `toolbar.*` | Top toolbar |
| `home.*` | Home dashboard |
| `model.*` | Model selection |
| `session.*` | Session management |
| `file.*` | File operations |
| `code.*` | Code block UI |
| `message.*` | Message actions |
| `forward.*` | Message forwarding |
| `lightbox.*` | Image lightbox |
| `tool.*` | Tool call display |

## Game-Local i18n

Games use a separate per-game translation system to keep modules self-contained:

```typescript
// src/routes/play/chess/i18n.ts
const labels = {
  en: {
    white: "White",
    black: "Black",
    check: "Check!",
    checkmate: "Checkmate!",
  },
  ko: {
    white: "백",
    black: "흑",
    check: "체크!",
    checkmate: "체크메이트!",
  },
};

export function $kt(key: string): string {
  const lang = getCurrentLocale(); // reads from global locale
  return labels[lang]?.[key] ?? labels.en[key] ?? key;
}
```

Usage in game components:
```svelte
<span>{$kt('check')}</span>
```

## Adding a New Key

1. Add the key to **both** language files:

```typescript
// src/lib/lang/en/index.ts
"mymodule.new_key": "English text",

// src/lib/lang/ko/index.ts
"mymodule.new_key": "한국어 텍스트",
```

2. Use in component:
```svelte
<script>
  import { t } from "$lib/i18n";
</script>

<p>{$t('mymodule.new_key')}</p>
```

## Adding a New Language

1. Create `src/lib/lang/<code>/index.ts` with all keys
2. Register in `src/lib/i18n.ts` dictionaries
3. Add locale option to settings UI
4. Add language label key: `settings.language.<code>`
